# Trelio Agent Workspaces

Официальный публичный дистрибутив плагина Codex и Claude для работы с
управляемыми Agent Workspaces и живыми навыками Trelio.

Patch `1.6.11` добавляет guarded перенос существующего досье между company и
project scopes с независимой проверкой manage-прав на исходную и целевую
области. Перенос сохраняет UUID, Git-историю, ревизии и task links.

Patch `1.6.7` разрешает владельцу или администратору компании менять
собственную прямую роль проекта через тот же guarded plan/apply flow:
company-wide доступ сохраняется, а подтверждение moderator grant/revoke
остаётся обязательным.

Плагин подключает:

- production MCP `https://trelio.ru/mcp` с OAuth 2.1;
- навык `trelio-workspace-worker` с регламентом Agent Run;
- bootstrap-навык `trelio-skill-catalog`, который загружает текущие назначения
  компании и проекта через MCP без фиксации версии в Run;
- навык `trelio-project-access` для точечного plan/apply управления прямыми
  ролями проектов только владельцем или администратором компании;
- стабильный host подписанных внутренних runtime-пакетов навыков: live resolve,
  Ed25519-проверка, content-addressed cache и запуск без shell;
- универсальный локальный host декларативных Remote MCP навыков: защищённый
  персональный credential, HTTPS/SSRF guard, protocol doctor и exact read-only
  allowlist перед каждым вызовом;
- постоянный skill-first routing gate через MCP `initialize.instructions`,
  который до выбора integration tool требует проверить exact company/project
  каталог и запрещает обход найденного навыка браузером или альтернативным
  транспортом;
- локальный Git bridge для открытия workspace, checkpoint и атомарной записи
  candidate revision с защитой от конфликтов версий;
- один scoped MCP-вызов для массового обычного поиска задач по отдельным
  синонимам, сокращениям и вариантам формулировки;
- private-встречи с отдельной ACL, расшифровкой, свободным итогом и
  подтверждаемым планом переноса контекста в задачи и workspace;
- ACL-фильтруемый поиск по принятым workspace-файлам и материализацию выбранных
  workspace как pinned read-only контекста под `context/related/`;
- прямые связи между задачами со свободным описанием смысла и отдельные
  company-level кейсы для действительно общего предмета;
- безопасное применение Agent Secrets через одноразовую выдачу конкретному
  локальному executable без вывода значения в MCP, prompt или shell-аргументы;
- переносимый TLS IMAP/SMTP CLI для первого навыка электронной почты без Gmail API.

При настройке Gmail CLI показывает прямую официальную страницу
[`myaccount.google.com/apppasswords`](https://myaccount.google.com/apppasswords),
удаляет визуальные пробелы из 16-символьного пароля приложения и открывает
защищённую одноразовую страницу `127.0.0.1` в браузере по умолчанию.
Терминальный ввод возможен только через явный флаг в видимом TTY.

Этот репозиторий является единственным каноническим источником плагина. В
основном Trelio-монорепозитории находятся backend и UI Agent Workspaces, но не
дублируемая копия клиентского дистрибутива.

## Работа с оператором

Плагин ведёт человека через результат, а не через технические детали Agent Run.
Перед записью агент обязан:

- сохранить handoff с итогом, подтверждениями, материалами, вопросами и
  конкретным действием оператора;
- при смысловых изменениях подготовить через Trelio один редактируемый manual
  comment: Codex и Claude Cowork показывают поле с кнопкой «Опубликовать», а
  CLI – текстовый fallback; новый вариант заменяет неопубликованный draft и
  заново собирает дельту после последнего реально опубликованного предложения;
- назвать человеку результат и следующий шаг, не подменяя их SHA, UUID или
  сообщением о том, что полезный текст находится «внутри candidate».

После успешных автоматических проверок candidate принимается без отдельного
подтверждения человека. Если `acceptedHead` изменился после старта Run, Trelio
отклоняет запись с `WORKSPACE_OUTDATED`: агент открывает новую версию и
переносит изменения осознанно. Ранее принятая версия восстанавливается новой
аудитируемой revision без переписывания Git-истории.
Успешный task-scoped accepted Run создаёт системный комментарий из handoff.
Последовательные Run одного пользователя за один календарный день компании
схлопываются в одну запись с раскрываемыми итогами каждого запуска.

Дополнительный контекст агент ищет только по необходимости. Каждый результат
и каждая связанная задача проходят обычную ACL заново. После прикрепления к
Run bridge открывает точный head только для чтения; `trelio-workspace context
attach --workspace <uuid>` прикрепляет новый контекст с актуальной локальной
lease, а `context sync` догружает уже выбранный контекст после `open`.

## Установка

Добавьте marketplace:

```bash
codex plugin marketplace add trelio-ru/agent-workspaces
```

Команда подключает default branch официального marketplace. Такой уже
подключённый источник обновляется так:

```bash
codex plugin marketplace upgrade
```

Если источник раньше добавлялся с `--ref vX.Y.Z`, он намеренно остаётся на
этом tag. Один раз переподключите его без фиксации версии:

```bash
codex plugin marketplace remove trelio-plugins
codex plugin marketplace add trelio-ru/agent-workspaces
```

Policy `INSTALLED_BY_DEFAULT` сразу устанавливает из marketplace `Trelio Agent
Workspaces`, поэтому отдельная команда `codex plugin add` не нужна. Откройте
`Plugins`, выберите плагин и завершите личный OAuth-доступ Trelio. После этого
начните новую задачу: уже открытая сессия не обязана перечитывать список
MCP-инструментов. Полностью перезапускайте Codex только если новая задача всё
ещё не видит tools или использует старую plugin-версию.

Если после обновления Trelio инструменту понадобится новый OAuth scope, его
стандартный `mcp/www_authenticate` challenge откроет нативную карточку
повторной авторизации. На старом Codex host агент сам запускает
`codex mcp login trelio` как fallback и ждёт завершения browser-flow.
Пользователь в любом случае лично проверяет и подтверждает новые права; агент
не получает доступ к token и не может обойти consent.

В новой задаче выберите первый starter prompt
`Настрой Trelio и доступные навыки для текущего проекта`. Агент проверит
доступную компанию, безопасно создаст или дополнит корневой `AGENTS.md`, без
тестового рабочего запуска подключит локальный компонент и предложит настроить
выбранные навыки. Общая конфигурация навыка и личное подключение разделены:
например, ненастроенный `1c-edo` показывается как
`требуется настройка администратором компании`, а пароль пользователя никогда
не запрашивается в чате.

При первом локальном `open` bridge создаст одноразовую pairing-заявку, а агент
сразу передаст её уже авторизованному MCP и повторит исходную команду. Код
пользователю не показывается, писать подтверждение в чат не нужно. Если текущая
approval-policy MCP-клиента требует подтверждать такие tool-вызовы, клиент сам
покажет одну штатную кнопку; при автоматическом режиме пользователь увидит
только уведомление, что устройство подключено. MCP token не передаётся bridge,
а отдельная узкая device-session сохраняется в приватном локальном файле и
используется во всех следующих Run без дополнительных MCP-запросов. На
macOS/Linux это
`~/.config/trelio/workspace-bridge/credentials.json` (`0700` для каталога,
`0600` для файла, owner/no-symlink checks и атомарная запись), на Windows –
`%LOCALAPPDATA%\Trelio\workspace-bridge\credentials.json` с ACL только для
текущего пользователя. Системная Связка ключей для bridge device-session не
используется; старое значение при наличии мягко переносится в файл. Если
локальная запись после exchange не прошла, bridge сам отзывает выданную
server-session. Права на рабочие правила, включая
`mcp:agent-instructions:manage`, остаются только у основного MCP-подключения.

В управляемой рабочей области ChatGPT/Codex администратор может импортировать
marketplace один раз и назначить плагин нужным ролям. OAuth всё равно проходит
каждый пользователь лично. Автоматическая установка не обходит policy рабочей
области: если администратор запретил плагин для роли, пользователь не сможет его
подключить самостоятельно.

Для Claude Code / Claude Cowork используйте marketplace этого же репозитория:

```text
/plugin marketplace add trelio-ru/agent-workspaces
/plugin install trelio-agent-workspaces@trelio-plugins
```

Назначения навыков в Trelio аддитивны: компания может включить навык всем,
проект – добавить свой. Отключение не удаляет личные навыки пользователя и не
является запретом. Обновлённая Markdown-инструкция навыка приходит при
следующем MCP-чтении, поэтому для неё не требуется новый Agent Run или ручная
синхронизация пользовательской папки. Исполняемая часть навыка публикуется
отдельным подписанным релизом во внутреннем каталоге Trelio. Перед каждым
запуском bridge сверяет exact release с сервером, а package скачивает только
при отсутствии проверенного digest в локальном cache.

Интерактивные данные входа skill runtime вводятся browser-first: системный
браузер открывает одноразовую tokenized-страницу на `127.0.0.1`, а runtime
проверяет exact loopback Host, same-origin submit, фактическую загрузку,
bounded body/timeout
и закрывает listener после результата. Нативные окна ОС не являются отдельным
штатным путём; terminal fallback возможен только явно в видимом TTY.
`autocomplete=off` считается best-effort hint, а не запретом password manager:
reusable secret-поле объясняет, что браузерную копию сохранять не нужно,
поскольку runtime отдельно сохранит проверенное подключение на устройстве.

Telegram runtime авторизует личную сессию через защищённую одноразовую страницу
на `127.0.0.1`, одинаково доступную на macOS и Windows. В системном браузере
можно выбрать код Telegram или QR. Телефон, код и 2FA остаются только в
локальном процессе и не попадают в MCP, argv, workspace или сервер Trelio.
Непустая подсказка 2FA из Telegram показывается рядом с полем пароля только на
этой локальной странице; она ограничивается по длине, HTML-экранируется и не
попадает в результат команды или terminal fallback.
Инструкция Telegram `1.1.5` перед подготовкой исходящего сообщения требует
прочитать последние 5–10 содержательных реплик exact диалога и сохранить
сложившиеся обращение, форму `ты/вы`, степень формальности и тон. Общий стиль
пользователя применяется только как fallback, если диалог этого не определяет;
в групповом чате учитывается стиль общения с конкретным адресатом.

## Безопасность

Публичный репозиторий содержит только клиентский дистрибутив. Публикация MCP URL
не открывает данные Trelio: MCP-запросы проходят OAuth, а bridge-запросы –
отдельную узкую device-session; оба контура повторяют обычные проверки доступа
компании, проекта и задачи.

Agent Secrets хранятся и расшифровываются на стороне Trelio, но Trelio не
исполняет пользовательские команды. MCP возвращает только безопасные описания
и одноразовый grant, а bridge внутри текущего Agent Run сверяет `runId` и
передаёт значение локальной программе через `stdin`, переменную окружения или
закрытый временный файл.

Host `1.4.8` дополнительно передаёт подписанному runtime только нормализованный
несекретный company connection и stable локальную identity из свежего resolve.
Перед этим он удаляет одноимённые host-controlled env родительского процесса.
Secret values в resolve не входят и не могут быть подменены обычным shell env.

Персональный Remote MCP PAT, напротив, вообще не передаётся Trelio: пользователь
вводит его в одноразовой loopback-форме, а plugin хранит значение в приватном
локальном integration namespace, привязанном к пользователю и fingerprint
декларации. В чат, prompt, workspace, открытый config и MCP tool arguments PAT
не попадает. SSE-ответ завершается по exact matching JSON-RPC `id`, а
абсолютный deadline не продлевается heartbeat-трафиком. Локальный browser
opener проверяет exit status, а handoff считается состоявшимся только после
exact GET одноразовой формы. Если macOS не доставила default open, host сам
проверяемо пробует Chrome и Safari; URL с nonce остаётся внутри процесса.
Форма отдельно объясняет, что browser-копия PAT не нужна: host сохранит
проверенное подключение локально, но не может отключить browser policy.
Долгое ожидание формы не блокирует другие JSON-RPC запросы этого stdio host:
клиентская отмена немедленно прерывает opener/HTTP, закрывает loopback listener
и не допускает позднюю запись credential.

Не добавляйте токены, локальные credentials и содержимое рабочих workspace в
issues или pull requests. Для уязвимостей используйте приватное сообщение через
GitHub Security Advisory.

## Версионирование

Версия плагина и публичный Git tag выпускаются вместе. Новый plugin release
нужен для изменений MCP/bootstrap/bridge host, но не для обычных исправлений
инструкции, Remote MCP декларации или исполняемого runtime конкретного навыка:
такие версии выходят во внутреннем каталоге Trelio. Production backend требует совместимую
опубликованную стабильную версию host для bridge-запросов. Поэтому обычный
marketplace подключается без `--ref` и перед новой работой обновляется командой:

```bash
codex plugin marketplace upgrade trelio-plugins
```

Minor release `1.5.0` переносит обязательную маршрутизацию Agent Skills на
постоянный bundled MCP слой. Навык каталога остаётся подробной инструкцией, а
защищённый runtime `AGENTS.md` повторяет gate внутри открытого Agent Workspace.

Patch release `1.5.1` убирает обязательную автопубликацию manual task comment.
Агент предлагает редактируемую смысловую дельту без остановки Run, а успешный
task-scoped accepted фиксируется отдельным группируемым системным комментарием
с итогами handoff.
Секреты, локальные личные сессии и подтверждение отправки этим релизом не
изменяются.

Patch release `1.5.2` делает `waiting_for_human` переносимым между
компьютерами. Перед блокирующим вопросом bridge сохраняет на сервере
проверенный draft и связывает с ним структурированный checkpoint. Повторный
`open` того же Run получает draft, открытые вопросы и следующий шаг, не меняя
accepted revision до обычного submit.

Patch release `1.5.3` добавляет переносимый MCP App для task-comment proposal.
Codex и Claude Cowork показывают редактируемое поле с кнопкой публикации, CLI
получает тот же текст как fallback. Сервер хранит один draft на задачу и
пользователя, защищает его ревизией и публикует exact отредактированный текст
идемпотентно; неопубликованное предложение не блокирует handoff или submit.

Patch release `1.5.4` добавляет структурированный результат task-scoped
handoff. Обычное выполнение переводит задачу в статус с kind `review`, а при
его отсутствии — в `done`; успешная проверка уже проверяемой задачи переводит
её в `done`. Прямое завершение требует явного разрешения или self-created
задачи того же пользователя, а незакрытые вопросы оставляют статус без
изменений.

Patch release `1.5.5` добавляет company policy моделей агентов. Bridge
передаёт локально наблюдаемые client/model/effort при start/claim, а
`PreToolUse` guard повторно проверяет закреплённую policy перед действиями
Codex и Claude Code. Неизвестные модели и клиенты, включая Claude Cowork,
управляются отдельными явными правилами allow/deny.

Patch release `1.5.9` устраняет лишний неуспешный запуск, когда
`trelio-workspace` не зарегистрирован в `PATH`. Агент заранее разрешает
логический launcher текущего плагина и при необходимости сразу использует
bundled bridge той же версии через Node.js 22+, не сканируя cache и не выводя
оператору техническое сообщение о штатном варианте установки.

Patch release `1.5.10` добавляет guided onboarding текущего Codex-проекта.
Первый starter prompt безопасно создаёт или дополняет локальный `AGENTS.md`,
проверяет pairing через `trelio-workspace login` без тестового рабочего запуска
и показывает живой каталог навыков. Навыки настраиваются только после выбора
пользователя; общий blocker отображается как
`требуется настройка администратором компании`, а project-only навыки
предлагаются при появлении точного project/task context.

Patch release `1.5.11` добавляет тихое self-update Codex plugin и task controls
в рабочий контур агента. Bridge обновляет только официальный marketplace в
отдельном процессе, ограничивает сетевые повторы и проверяет exact установленный
entrypoint; при hard gate он может продолжить исходную команду новым bridge в
той же задаче. `get_task` показывает общие и только собственные личные
контроли, а новые MCP tools позволяют создавать, менять и снимать их с теми же
ACL и правилами приватности, что и web-интерфейс. Наступление даты не
уведомляет; снятие общего контроля пишет системный комментарий и уведомляет
аудиторию задачи. Само завершение Run или изменение статуса контроль не
снимает.

Minor release `1.6.0` добавляет server-managed платформенные правила.
Bridge отправляет SHA-256 локального cache на compatibility preflight,
проверяет и атомарно сохраняет новую revision, повторяет preflight с новым hash
до отдельного ответа `current`, а затем подтверждает exact hash при
start/claim. Backend закрепляет эту revision за Agent Run вместе с
company/project правилами. Поэтому правила оформления результата, включая
кликабельные локальные ссылки только на содержательные анализы, выводы, отчёты,
расчёты, планы и подготовленные документы, можно публиковать в Trelio без
нового plugin release. Активный Run продолжает использовать свой immutable
snapshot.

Patch release `1.6.1` добавляет отдельный `trelio-project-access` для
точечного управления прямыми ролями проекта. Навык всегда разрешает точный
`memberId`, сначала получает dry-run plan и применяет только связанный с ним
`expectedStateHash`. Прямую команду на участника, наблюдателя или удаление
можно выполнить без второго вопроса; предложение агента и любая неоднозначность
требуют показа плана. Назначение и отзыв модератора всегда требуют отдельного
явного подтверждения. Project moderator не может инициировать этот MCP-поток,
групповые и массовые обходы запрещены. Для старого OAuth-подключения требуется
повторный consent на `mcp:project-access:manage`. После публикации `1.6.1` в
marketplace backend patch поднимает общий minimum до этой версии, поэтому
старый bridge обновится штатным self-update перед следующей Agent Workspace
операцией.

Patch release `1.6.2` добавляет сохраняемый журнал работы агента. Bridge
создаёт стандартный `WORKLOG.md` только когда workspace ещё не содержит этот
файл, а принятую или настроенную версию не подменяет новым шаблоном. После
чтения контракта агент создаёт отдельную запись текущего Run в `worklog/`, не
переписывает предыдущие записи и не накапливает все запуски в одном растущем
Git blob. Запись содержит значимые действия, повлиявшие указания оператора,
краткие основания решений, проверки, результат, вопросы и следующий шаг; в неё
не попадают внутренняя цепочка рассуждений, полная переписка, рутинные команды,
сырые ответы инструментов и секреты. После публикации `1.6.2` backend patch
поднимает общий minimum до этой версии.

Patch release `1.6.3` исправляет Windows ACL guard для локальных приватных
каталогов и файлов. Путь и тип больше не передаются позиционными аргументами
после `powershell.exe -Command`: Windows PowerShell не связывает их с
`param(...)`, из-за чего `$TargetPath` мог оставаться пустым. Bridge передаёт
UTF-8 Base64 пути и фиксированный тип только в environment дочернего процесса,
валидирует их перед `Set-Acl`, загружает inbox security module по `$PSHOME` и
сохраняет fail-closed проверку владельца и отсутствия посторонних ACL. После
публикации `1.6.3` backend patch поднимает общий minimum до этой версии.

Patch release `1.6.4` сохраняет только DACL локального приватного пути через
typed .NET API. Bridge читает Owner отдельно и меняет его только отдельным
owner-only descriptor-ом, если elevated-процесс создал путь с владельцем
`Administrators`; DACL записывается другой операцией. Group и SACL не
запрашиваются, поэтому `SeSecurityPrivilege` не требуется. Windows CI
дополнительно запускает реальный guard под отдельной стандартной локальной
учёткой и повторяет hardening существующего файла. После публикации `1.6.4`
backend patch поднимает общий minimum до этой версии; миграции, новые
постоянные env и OAuth scopes не требуются.

Patch release `1.6.5` делает workspace object pointer совместимым с Windows
checkout: parser принимает канонический LF и полностью CRLF-файл, который мог
создать `core.autocrlf`. Mixed line endings и одиночный carriage return
отклоняются, а SHA-256, размер, content type и точная структура остаются
fail-closed. Большие исходные файлы и Excel-модели не переписываются. После
публикации `1.6.5` backend patch поднимает общий minimum до этой версии.

Patch release `1.6.6` позволяет агенту восстановить устаревший OAuth grant без
ручной навигации в Plugins. Сначала используется нативная карточка повторной
авторизации из `mcp/www_authenticate`; если Codex host её не показывает, агент
сам запускает `codex mcp login trelio`, ждёт browser consent и один раз
повторяет исходное безопасное чтение. Пользователь по-прежнему лично
подтверждает новые права, а повторный grant сохраняет ранее выданные scopes.
Миграции и новые постоянные env не требуются.

Patch release `1.6.11` добавляет guarded
`plan_dossier_transfer` → `apply_dossier_transfer` для переноса существующего
досье из компании в проект, между проектами и обратно в компанию. Actor должен
независимо управлять обеими областями; незавершённые Run блокируют перенос, а
company target требует отдельного подтверждения широкой видимости. UUID,
accepted Git history, ревизии и task links сохраняются. Миграции, env и новые
OAuth scopes не требуются; live plugin policy Trelio поднимается только после
публикации плагина.

Patch release `1.6.10` добавляет в task-comment proposal осознанный выбор
файлов из принятого task-scoped Run. Агент предлагает только важные итоговые
результаты и действительно полезные промежуточные материалы; пользователь
видит точные карточки, может убрать лишнее, а обычные вложения задачи создаются
только при нажатии «Опубликовать». Backend transport уже выпущен отдельно;
миграции, новые env, OAuth scopes и повышение plugin minimum не требуются.

Patch release `1.6.9` поднимает кадровый 1С runtime до `1.0.5`, потому что
immutable production version `1.0.4` уже занята прежним shared-provider
артефактом. Поведение независимого browser-first подключения не меняется.

Patch release `1.6.8` переводит Email setup с нативных окон на защищённую
browser-first loopback-страницу, добавляет каноническое предупреждение о
возможном password-manager prompt в Email, Remote MCP, Telegram 2FA и 1С и
закрепляет отдельные настройки и локальные credentials у каждого 1С-навыка.
`autocomplete=off` остаётся только best-effort hint; terminal fallback
допустим лишь явным флагом в видимом TTY.

После обновления начните новую задачу или перечитайте plugins штатной командой
клиента; полный restart оставьте только для случая, когда новый контекст всё
ещё использует старую версию. Источник, закреплённый на `--ref vX.Y.Z`,
перестанет открывать Agent Workspace после следующего plugin release; pin
допустим только как короткая
диагностика или rollback до восстановления совместимой текущей версии.

Подробности находятся в
[`plugins/trelio-agent-workspaces/README.md`](plugins/trelio-agent-workspaces/README.md).
