# Финальная проверка сохранения контекста

Полностью прочитай файл и выполни проверку до итогового ответа после
содержательной работы Trelio, включая внешний поиск, анализ и новые сведения в обсуждении
без task/Run. Прежний accepted Run не подтверждает позднее дополнение.
Чистая настройка и maintainer-работа не требуют бизнес-Workspace.

Примени загруженные exact effective rules либо pinned rules Run. При их
отсутствии выполни exact-чтение цели с правилами или `get_agent_instructions`
для известной компании/проекта; после compaction перечитай потерянный текст.
Каталог и ответ интеграции не заменяют правила; неизвестная/legacy policy
не становится `maintain`. Используй только серверный encrypted provider route.

Сравни новые факты, выводы, решения, материалы и вопросы с подходящим принятым
контекстом. Переиспользуй актуальное чтение. Для определения цели нужен
`scope-and-context.md`, для accepted files – `accepted-workspace-read.md`
или штатное точечное чтение. Отсутствие Run, задачи, поискового совпадения
или команды «сохрани» не означает отсутствия дельты. Новая цель создаётся
по действующим правилам; неоднозначную привязку не заменяй широкой аудиторией.

Заверши оценку одним исходом:

- `saved`: результат проверен в нужных файлах, подтверждена accepted revision
  точного Workspace/Run/candidate head с этой дельтой. При неоднозначном finish
  сначала установи серверное состояние; при сомнении прочитай принятый файл.
  Локальный output, Run, checkpoint/draft, handoff или ответ без acceptance
  недостаточны. Не повторяй неоднозначную запись вслепую.
- `no_new_context`: сравнение не выявило существенной дельты либо результат уже
  зафиксирован. Не дублируй сохранённую нативную операцию ради проверки.
- `not_authorized`: запись запрещена пользователем или не разрешена правилами.
  Неизвестные правила сначала загрузи; недоступное чтение означает `blocked`.
- `blocked`: нужная запись не завершена из-за конкретной ошибки, ACL, конфликта
  или неясной цели. Сообщи причину и следующий шаг, запроси лишь недостающее
  решение и не заявляй о сохранении.

Если существенная дельта требует разрешённой записи, сам открой/продолжи Run
по `agent-run.md` и доведи `finish` до подтверждённого принятия перед ответом;
для task scope загрузи соответствующие worker references. Сохраняй краткий
результат с источниками, отделяя факты от предположений. Не проси пользователя
запускать Run. Не обходи конфликт и не меняй правила ради фиксации.

Соблюдай `manual/capture/maintain`: проверка не разрешает capture переписывать
канонический материал, не отменяет прямой запрет пользователя, ACL, отдельные
подтверждения встреч, Agent Secrets, аудитории и task/external mutations.
Не копируй закрытое содержимое ради проверки. Новых полномочий она не даёт.

Исходы – критерии завершения, не серверная аттестация диалога и не новый tool.
Не создавай пустой Run или файл отчёта. Затем выполни применимые независимые
проверки задачи/proposals. Сообщи кратко о сохранении или значимой блокировке;
технические исходы и ритуальное отсутствие изменений в ответ не выноси.
