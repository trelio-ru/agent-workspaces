# Run в рамках задачи

Полностью прочитай файл для task-scoped Run с записью вместе с `agent-run.md`
и процедурами комментария, статуса и чек-листа из основного навыка.

<a id="choose-the-handoff-outcome"></a>

## Выбери итог передачи

Каждый handoff задачи передаёт ровно один `taskOutcome` по готовности всей
задачи и semantic status kind, а не только последней просьбы или локализованного
имени/кода. Outcome – рекомендация; принятие Run не меняет статус:

- `work_completed`: вся задача готова. Рекомендуй первый допустимый переход
  в `review`, либо `done`, если review отсутствует.
- `review_passed`: только после успешной проверки в этом Run задачи, уже
  находящейся в semantic `review`; рекомендуй `done`.
- `direct_completion`: только при прямой просьбе пропустить проверку,
  разрешающем pinned rule либо если тот же авторизованный пользователь
  создал задачу и назначил её себе. Рекомендует `done`; даже тогда предпочитай
  `work_completed` без конкретной причины пропустить review.
- `no_status_change`: частичная/информационная работа, неуспешное review или
  незакрытые вопросы, блокирующие завершение. Безопасное значение, если
  прямая просьба может быть уже всей задачи.

`questions` и `no_status_change` нужны, только если ответ необходим для
выполнения, проверки или решения задачи. Необязательные поля и будущие улучшения
оценивай по [правилам готовности](task-status-proposals.md#assess-completion-across-the-whole-task),
сохраняя посторонние поля.

<a id="submit-and-propose"></a>

## Отправь и подготовь предложения

Принятый submit создаёт системный комментарий из неизменяемого handoff
и рекомендацию статуса. Последовательные принятые Run одного пользователя
группируются за календарный день компании с доступными деталями каждого.

После принятия один раз вызови `get_task_review_context` с точной задачей/Run
и только нужными `proposalKinds`, включая `comment` для обязательного
сообщения человеку. Он возвращает свежие core/deadline, видимые controls,
полный checklist и выбранные proposal contexts. Используй общие верхнеуровневые
controls/checklists вместе с proposal state и переиспользуй снимки для
соответствующих процедур, без повторов `get_task`, sections и одиночных context
reads. Существенное промежуточное изменение/конфликт требует нового чтения.
Если backend выбрал local action, следуй ему, не подменяй mirror/remote plaintext.

По этим свежим снимкам выполни три независимые процедуры:

- `task-comment-proposals.md` – обязательный комментарий человеку;
- `task-status-proposals.md` – повторная оценка всей задачи, включая ранее
  записанный `no_status_change`, до необязательных вопросов;
- `task-checklist-proposals.md` – оценка каждого пункта даже после частичной работы.

До записи перечисли все карточки. Для двух и более – `task-proposal-bundles.md`
и один `render_task_proposals`. Недостающие scope/permissions предложения
не отменяют принятый результат. Итог сообщи по `agent-run.md`.
