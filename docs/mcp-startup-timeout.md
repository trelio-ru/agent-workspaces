# Время подключения MCP в Codex

Поставляемые регистрации `trelio-runtime` и `trelio-runtime-local` задают
`startup_timeout_sec=60` для подключения и чтения каталога. Codex применяет
пользовательские overrides с прежним приоритетом.

## Почему это изменение stable shell

На медленном соединении загрузка удалённого каталога через `tools/list` может
занять дольше стандартных 30 секунд. Например, 16 ответов по 61 КБ на общей
линии 32 КиБ/с требуют около 30 секунд одной передачи. При одновременном
переподключении загруженных чатов локальный MCP также может выйти за этот срок
до завершения `initialize`. Codex помечает соединение как failed и пропускает
его инструменты.

Загрузчик до открытия stdio проверяет актуальность подписанного runtime.
При одновременных запусках один процесс проверяет канал под общей блокировкой.
Остальные переиспользуют подтверждение, если оно получено после начала их
запуска для того же origin, версии плагина и текущего указателя. Каждый процесс
проверяет файлы выбранного runtime. Отметка создаётся только после успешной
проверки. Более поздний отдельный запуск заново проверяет канал. Бюджеты
загрузчика 20 и 25 секунд продолжают действовать.

Манифест задаёт deadline Codex, а загрузчик выполняется до запуска signed
runtime. Поэтому обновление только backend или signed runtime не меняет эти
настройки и ожидание.

## Проверка и доставка

`tests/plugin-shell.test.mjs` проверяет значения манифеста и несколько
одновременных процессов с loopback-каналом подписанного runtime. Один запрос
метаданных обслуживает все пересекающиеся запуски с текущей, новой и ещё не
установленной версией. `tests/codex-tool-exposure.py` запускает настоящий Codex
с изолированным плагином и проверяет, что локальное рукопожатие и удалённый
каталог через 31 секунду дают рабочие инструменты в Code Mode. Обе проверки
используют синтетические данные.
Backend проверяет полный каталог настоящим SDK через ограниченный HTTP proxy:
один чат с прежними 30 секундами и 16 чатов с 60 секундами, общие 32 КиБ/с,
RTT 500 мс, identity/gzip parity. Сжатый ответ не меняет decoded schemas и ACL.

Настройка доставляется обычным релизом плагина. Для уже открытого клиента
действуют штатное обновление и переподключение, после чего требуется реальное
чтение. Возврат изменения означает восстановление прежнего default в manifest;
локальные credentials, OAuth, pairing и trust не сбрасываются.
Релиз требует отдельного [согласования оператора](plugin-setup-and-policies.md#operator-release-approval).
