# Время подключения удалённого MCP в Codex

В поставляемой регистрации Codex сервер `trelio` задаёт
`startup_timeout_sec=60`. Это ограниченный default для первоначального
подключения и чтения каталога, а не изменение пользовательского `config.toml`
и не увеличение времени бизнес-команд. Local `trelio-remote-skills`, Hooks,
OAuth, trust, runtime admission и настройки других клиентов сохраняются.

## Почему это изменение stable shell

На медленном соединении клиент может превысить исходные 30 секунд именно при
`tools/list` и не выдать инструменты модели. Серверное gzip уменьшает каталог,
но при одновременном переподключении нескольких чатов каждый клиент получает
свою копию. Например, 16 ответов по 61 КБ на общей линии 32 КиБ/с уже требуют
около 30 секунд одной передачи, без handshake и задержки сети.

Тайм-аут задаёт Codex до получения ответа MCP. Backend instruction, новый
signed runtime либо повторный toggle не могут увеличить этот срок. Поэтому
изменяется только владеющая client declaration в Codex manifest; это дефект
pre-runtime подключения stable shell, а не повод менять bundled навыки.
Версии ABI и minimum не повышаются: прежние клиенты продолжают работать,
пользовательские overrides сохраняют свой приоритет.

## Проверка и доставка

`tests/plugin-shell.test.mjs` проверяет значение 60 в remote Codex declaration
и неизменность остальных client declarations. `tests/codex-tool-exposure.py`
запускает настоящий Codex с изолированной synthetic установкой, читает default
из plugin manifest без ручной записи второго сервера и проверяет, что ответ
каталога через 31 секунду действительно даёт прямую схему модели. User config,
токены и сервис Trelio в этой проверке не используются.
Backend проверяет полный каталог настоящим SDK через ограниченный HTTP proxy:
один чат с прежними 30 секундами и 16 чатов с 60 секундами, общие 32 КиБ/с,
RTT 500 мс, identity/gzip parity. Сжатый ответ не меняет decoded schemas и ACL.

Настройка доставляется обычным релизом плагина. Для уже открытого клиента
действуют штатное обновление и переподключение, после чего требуется реальное
чтение. Возврат изменения означает восстановление прежнего default в manifest;
локальные credentials, OAuth, pairing и trust не сбрасываются.
Релиз требует отдельного [согласования оператора](plugin-setup-and-policies.md#operator-release-approval).
